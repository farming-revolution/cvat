# Farming Revolution 1.0 acceptance test

The format retains standard image annotations and adds a namespaced native archive under meta. It is registered for both import and export, so normal GUI format discovery and API requests expose it without a custom UI. Task/job imports and project imports remap native IDs and verify grouping/content after writing inside the existing import transaction.

Run farming_revolution_roundtrip.py in a disposable CVAT server image with PYTHONPATH=/home/django and network disabled. It replaces the database configuration with SQLite :memory: before Django initializes and creates only ephemeral fixture tables. Never run it through a production manage.py shell.

Covered: native/independent annotations, interpolation without archive mutation, outside/reappearance, tags and healthy zero, transactional task import/readback, failed import rollback, stable re-export at a different server, unchanged standard format, cache invalidation, multi-task project export/import, job round trips and ambiguous duplicated identity rejection.

The registry JSON is generated by AI's annotation_pipeline.registry CLI. Preserve existing fork server fixes when building the backend image. Deploy cvat_server plus export/import format workers after draining jobs; retain previous images. No database migration is introduced.

Native recreation into an empty project delegates media/task creation to CVAT's existing machinery with predefined source order. Real media ingestion and multi-segment production imports require an approved staging acceptance run; the isolated test exercises existing-project imports and single-segment task/job imports.
